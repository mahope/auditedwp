GitHub notifications on Windows: the five options that actually work

Updated August 2026 · 6 min read

GitHub ships official desktop apps for macOS and Windows — but neither puts notifications in your system tray with an unread count. On Windows you're left choosing between browser notifications, email, or a third-party tool. Here are the five realistic options, what each costs, and where they fall short.

Option 1: Browser notifications from github.com

In Chrome or Edge, open github.com, click the lock icon in the address bar, and set Notifications to Allow. GitHub then pushes web notifications for your watched activity while a tab is open.

The catch: it only works while a GitHub tab is open (Chrome can deliver them in the background for installed PWAs, but reliability varies). If the browser is closed, you get nothing.

Option 2: Email notifications

Under Settings → Notifications you can route everything to email. This is the default for most people and works everywhere Windows does.

The catch: volume. Active developers get hundreds of notification emails per day, which is why so many people end up muting them — and then miss the mentions that mattered. See our guide on turning off GitHub email notifications safely.

Option 3: The Windows Notification Assistant + github.com as an app

You can "install" GitHub as a PWA from Chrome (Menu → Cast, save and share → Install page as app). It gets its own window and registers with Windows notifications, which makes Option 1 noticeably more reliable.

The catch: still no aggregated unread count outside the app, and no way to see PRs, issues and mentions at a glance without opening it.

Option 4: Third-party open-source tray apps

Gitify is the best-known option and runs on Windows. It sits in the tray, polls the GitHub notifications API with your personal access token, and shows an unread count with a popup list. We compared it in detail here.

Octobox is a web-based inbox for GitHub notifications — not Windows-native, but usable in any browser if you want triage features like archiving and filtering. See how it compares.

The catch: both require creating a personal access token and keeping on top of community-maintained projects. Check each project's release activity before relying on it.

Option 5: A dedicated menu bar / tray client

If you want this to just work — a tray icon with an unread count, a popup list of PRs, issues and mentions, one click to open the item on GitHub — that's exactly what DevNotify does. It uses your own read-only token, talks directly to the GitHub API, and sends nothing anywhere else.

It's currently available for macOS. A Windows build is planned — join the list on the home page and you'll be told when it ships.

Which should you pick?

  • Light user: PWA + browser notifications (Options 1+3) cost nothing.
  • Team member drowning in email: fix the email routing first, then add a tray tool.
