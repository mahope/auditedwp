Still getting GitHub notification emails after unsubscribing

Updated August 2026 · 4 min read

You clicked Unsubscribe on the issue. Two days later, another email about it lands in your inbox. This isn't a glitch — GitHub has three separate switches that control email, and unsubscribing from a thread only touches one of them.

Switch 1: Thread subscription (the one you clicked)

Unsubscribe on an issue or PR stops notifications for that thread — unless someone @mentions you again, which always notifies regardless of subscription state. If the emails you're getting are about threads you never explicitly touched, this switch was never the one in control.

Switch 2: Repo watching

If you're still watching the repo, every new issue, PR, and release generates email no matter what you did to individual threads. Check at github.com/watching — the list shows everything you watch across all accounts. Unwatch repos you've stopped contributing to, or switch them to "Releases only" / "Participating only" via each repo's Watch dropdown. This is the switch most people miss: thread-level unsubscribes are fought by watch-level subscriptions above them.

Switch 3: Global notification delivery settings

github.com/settings/notifications controls how each notification type is delivered: Web, Email, or both. If "Email" is checked for Participating, Mentions, CI activity, etc., any event that survives switches 1 and 2 still produces mail. Options here:

  • Email off entirely for events you handle on the web — web notifications keep working.
  • "Only receive email notifications for participating and @mentions" — the single biggest noise reducer most people have never enabled.
  • Per-repository overrides further down the same page: route specific repos to a separate address or suppress their email completely while keeping web alerts.

The 10-minute durable fix

  1. github.com/settings/notifications → enable "participating and @mentions only" for email.
  2. github.com/watching → unwatch or downgrade everything you don't actively follow.
  3. For lingering threads: unsubscribe individually, accepting that new @mentions will still notify (that's usually what you want).
  4. Turn off automatic watching under Settings → Notifications so joining an org doesn't re-flood you.

After that, your inbox stays quiet and github.com's inbox becomes the single source of truth. Our full walkthrough with screenshots-level detail is in how to cut GitHub notification noise.

If email is genuinely broken, not just noisy

Getting zero GitHub email when you should get some is different: check your spam filter for notifications@github.com, verify the address under Settings → Emails, and confirm your commit email vs account email confusion isn't routing mail somewhere unexpected.
